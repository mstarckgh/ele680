# ELE680 – 24 h-ahead electricity load forecasting: LSTM/GRU/TCN/CNN-GRU vs seasonal baselines

One-shot 24 h forecast of 10 clients of UCI ElectricityLoadDiagrams20112014 (hourly mean). I compare LSTM, GRU and
TCN of matched size (Bai et al. 2018, Lai et al. 2018), a simplified CNN-GRU hybrid, a residual formulation
(network predicts a correction to last week's load or to the four-week mean), and non-learned seasonal baselines,
with paired day-level evaluation. The report is in `report/report.md`.

## Setup
```bash
# local (cluster: see below)
uv venv --python 3.12 && source .venv/bin/activate
uv pip install torch numpy pandas matplotlib pyyaml pyarrow pytest
./scripts/download_data.sh          # -> data/raw/LD2011_2014.txt
pytest tests                        # causality, receptive field, paired-analysis and baseline checks
```
Clients are chosen once (seeded, no zero-load hours since 2012) and stored in `configs/clients.json`.
Chronological split 70/10/20 from 2012-01-01; z-scoring uses train statistics only.

## Experiments
`configs/*.yaml` (46 files, generated by `scripts/make_configs.py`), 5 seeds each:

| prefix | what |
|---|---|
| `main_{lstm,gru,tcn}` | L=168, parameter-matched (~65–70k params) |
| `len_<model>_L<L>` | input-length sweep L ∈ {24, 72, 336, 672} |
| `rf_tcn_n<n>` | TCN depth/receptive-field ablation at L=672 (n=7 is `len_tcn_L672`) |
| `abl_{l1,res,res_l1}_<model>_L<L>` | L1 loss / residual-to-last-week (needs L >= 168) ablations |
| `abl_res4[_l1]_<model>_L672` | residual on the mean of the last 4 weeks (`residual: mean4`, needs L >= 672) |
| `rfres_tcn_n<n>` | residual TCN receptive-field ablation at L=672 (n=7 is `abl_res_tcn_L672`) |
| `main_cnngru`, `abl_res_cnngru_L<L>` | hybrid: causal conv front-end + GRU (~68k params), plain and residual |

Single run: `python -m src.train --config configs/main_tcn.yaml --seeds 5` → `results/main_tcn.json`
(add `--save-preds [--suffix _preds]` to also store test forecasts in `results/preds/`).

## Reproducing the report
1. **Data:** `./scripts/download_data.sh`.
2. **Naive baselines:** `python -m src.run_baselines` → `results/baselines.json`. The multi-week averages
   (`mean_2w`, `mean_4w`, `median_4w`) are computed inside `src.analyze`.
3. **All configurations** (mean ± std tables, Sec. 3.1, 3.3), 5 seeds each; pick one:
   - Gorina4 (manual GPU reservation, no Slurm): `./scripts/gorina4_setup.sh` once, then
     `./scripts/run_gpus.sh "0 1 2" 5` (one process per listed GPU; skips configs that already have a result file).
     Subsets via a glob, e.g. `./scripts/run_gpus.sh "0 1" 5 'configs/rfres_*.yaml'`.
   - Slurm cluster: see below.
   - Local, sequential: `scripts/run_all.sh`.
4. **Forecasts for the paired analysis** (Sec. 3.2, 3.4, 3.5): `./scripts/save_preds.sh "0 1 2"` retrains the twelve
   configurations used there with `--save-preds` (`main_*` and `abl_res*` with suffix `_preds`, the `abl_res4_*` runs
   under their own name) and writes `results/preds/*.npz`. The retrained runs differ from step 3 by about the seed spread.
5. **Tables, figures, paired tests:**
```bash
python -m src.plots                                   # mean tables, figures/{input_length,residual_length,rf_residual}.pdf
M="abl_res_tcn_L168_preds abl_res_gru_L168_preds abl_res_cnngru_L168_preds abl_res_l1_tcn_L672_preds"
python -m src.analyze $M                              # MAE, per-client WAPE, paired vs naive_168h
python -m src.analyze $M --ref abl_res_gru_L168_preds # paired vs the residual GRU
python -m src.analyze $M --ref mean_4w                # paired vs the four-week mean
python -m src.analyze abl_res4_tcn_L672 abl_res4_l1_tcn_L672 abl_res4_gru_L672 --ref mean_4w
python -m src.analyze $M --fig figures/horizon_residual.pdf   # per-forecast-hour figure
```
   `--ref` may be any listed name or a baseline (`naive_168h`, `naive_24h`, `mean_2w`, `mean_4w`, `median_4w`).
   Paired differences use only the days both models cover (a window needs L hours of history inside the test split,
   so L=672 models are scored on 191 days and L=168 models on 212); intervals are 7-day moving-block bootstrap.

### UiS GPU cluster with Slurm (follows https://gitlab.ux.uis.no/unix/gpu)
```bash
ssh $USER@gorina11.ux.uis.no
cd /bhome/$USER && git clone <this repo> ele680 && cd ele680
./scripts/download_data.sh                    # on the login node; GPU jobs need files under /bhome
mkdir -p logs
sbatch scripts/slurm_setup.sbatch             # conda env, no GPU; wait for it to finish
sbatch scripts/slurm_baselines.sbatch         # cheap, CPU only
sbatch --array=0-$(( $(ls configs/*.yaml | wc -l) - 1 )) scripts/slurm_array.sbatch   # one task per config
```
Check scripts first with `sbatch --test-only <script>`. Adjust `--time` if tasks time out (a TCN at L=672 needs about
10 min per seed on a P100). The array task index is the position of the config in the sorted file list.

## Layout
`src/data.py` pipeline · `src/models.py` LSTM/GRU/TCN/CNN-GRU · `src/train.py` training/eval (residual variants) ·
`src/metrics.py` MAE/RMSE/RSE/CORR · `src/baselines.py` seasonal baselines · `src/analyze.py` per-client WAPE,
paired comparison, horizon figure · `src/plots.py` tables and figures · `scripts/` run helpers · `tests/` ·
`results/` per-config JSON, `results/preds/` test forecasts · `report/report.md` the report.

## References
Bai, Kolter & Koltun (2018), *An Empirical Evaluation of Generic Convolutional and Recurrent Networks for Sequence Modeling*.
Lai et al. (2018), *Modeling Long- and Short-Term Temporal Patterns with Deep Neural Networks*, SIGIR.
The TCN is written from scratch following the architecture in Bai et al.; the CNN-GRU is my own simplified design
inspired by LSTNet. No external code is used.
